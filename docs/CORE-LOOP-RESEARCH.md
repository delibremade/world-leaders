# Core loop research (G1-G4 and the interaction model)

Research only. No gameplay code. Written 2026-10-12 against v0.85.0 for `docs/CORE-LOOP-SPEC.md`. Owner request: reference implementations per epic (study-only where GPL/AGPL), real data sources with licence verdicts, a concrete model per epic that fits the existing tick, interaction-model research, and a sequenced build plan with issue-ready acceptance criteria.

**Verdict:** every epic has a proven reference and a redistributable data source, and all four fit the current month loop as new phases in `MONTH_PHASES` plus new `STATE_FIELDS` entries, with the vitals' mean-reversion targets re-pointed at produced values instead of constants. The one structural gap is domestic geography: the engine has ten world regions and no domestic regions, so G4's logistics needs a small new registry. The one structural risk is parity: G1 and G2 end byte-parity for `economy` and `research`, the way E4 ended it for minerals; the guard becomes invariants and seeded tests. Build G1, then G3 (smallest, gives the missing domestic loss), then G2, then G4. The spec says G1, G2, G3, G4; the swap is a recommendation, reason in section 5.

**How this was sourced (read before trusting a licence line).** The session's network policy refused every outbound page fetch except github.com (CONNECT 403; see the proxy's recent failures). Wiki, forum and licence pages were therefore read through web-search result snippets of the linked page, marked **[snippet]**. Anything read from a repository page, a LICENSE file or shipped game data on GitHub is marked **[repo]** and is solid. Anything that could not be confirmed is marked **unverified**. Before a data file ships, open each licence URL in a browser and confirm the quoted sentence.

Effort scale (from QOL-RESEARCH): **S** one PR under ~300 lines with tests. **M** one PR, 300 to 800 lines, tests, 390px screens. **L** engine change or multi-PR, parity re-baseline, new invariants.

## 3. Model proposal per epic

Common rules: every new top-level field is JSON, has a `newX(nid)` constructor, a loader default for old saves, and at least one `V57_INVARIANTS` row. Every formula is one exported function in `src/sim/formulas.js` with a `test/formulas.test.js` case. Rival nations run the same code on coarser data (national aggregates, no domestic regions) so the AI nations' isolation caps (F13) and sanctions (F14) use the same functions as the player's. Phase order after the epics: **pops, sectors, economy, research, minerals, forces, bases, pressure, intelOps, alliances, market, statecraft, counterIntel, politics, world**.

### 3.1 G1 pops

**State** `g.pops` (`newPops(nid)` from `src/data/pops.js`):
```
{ nid,
  c: { a0_14:{none,basic,sec,ter}, a15_24:{...}, a25_54:{...}, a55_64:{...}, a65p:{...} },  // thousands
  part: 0..1,                 // labour-force participation (WDI SL.TLF)
  jobs: { [sector]: { basic, sec, ter } },   // filled by G2; MVP: one 'employed' number
  mig: { net, push },         // net migrants/month, current push 0..1
  rates: { cbr, cdr, school: {basic, sec, ter} },   // calibrated per nation from WPP and WDI
  base: { pop, ter } }        // 2024 anchors for conversion and bounds
```
**Monthly update** (phase `pops`, first):
1. Ageing: move `n / (bandYears × 12)` from each band to the next (a monthly slice of the Leslie step).
2. Births into a0_14: `pop × cbr/12 × (1 − 0.10 × terShare) × (1 − 0.4 × max(0, unemp − 5)/20)` (Vic3 modifiers, scaled).
3. Deaths per band: `n × cdr_band/12 × (1.3 − 0.6 × healthcare/100)`.
4. Schooling flows inside a15_24: `none→basic`, `basic→sec`, `sec→ter` at `rate_e × (alloc.education/100)^0.5 × capacity_e`; `capacity_e` is the services sector share (G2) or 1 before G2.
5. Migration: `push = clamp(0.4 × (60 − stability)/60 + 0.3 × max(0, unemp − 5)/15 + 0.3 × (1 − wageRatio), 0, 1) × (1 + brainDrain trait)`; `emig/mo = pop15_54 × 0.0008 × push`, tertiary leaves at 2× weight; `immig/mo = pull × jobsOpen` with the Vic3 weights (+1.5 per 10K open jobs, −1 per 10K unemployed).
6. Outputs written as **targets** for `naturalDrift` (replace `e.education`, `e.healthcare`, `e.foodSecurity`, `e.unemployment` with selectors): education target = 100 × Σ w_e × n_e / n over ages 15 to 64 with w = {none 0, basic 0.35, sec 0.7, ter 1.0}; healthcare target = 100 × clamp(healthSpendPerCapita / need, 0, 1) where need rises with the 65+ share; unemployment target = (labourForce − Σ jobs)/labourForce; food target from G2 agriculture (1.0 before G2).
7. `MANPOWER.milAge` becomes a15_24 + a25_54 × 0.5 read from pops; recruits read `pops` unemployment.

**Formulas** (`formulas.js`): `ageStep(c)`, `births(pops, stats)`, `deaths(pops, stats)`, `schoolFlow(pops, alloc, capacity)`, `migPush(stats, trait)`, `migNet(pops, stats, jobsOpen)`, `schooledShare(c)`, `labourByEdu(pops)`.
**Invariants:** every cohort count finite and ≥ 0; total within 0.5× to 2× of `base.pop`; Σ jobs ≤ labour force; education and healthcare targets in [0, 100]; the player's `pops.nid` equals the player.
**MVP that fits the tick:** national only (no regions), five bands × four tiers, crude rates per nation, schooling driven by the existing education budget slider, emigration from stability and unemployment, three vitals re-targeted. Data for the eight playable nations plus the major rivals. Parity ends for `economy`; goldens re-baselined citing the issue.
**Done-when test:** seed run, education alloc 200 versus 50 for 120 months: tertiary share differs by ≥ 8 points, `forceQuality` by ≥ 5 after month 60, `rdSpeedMult` by ≥ 0.05; `__wl.field('stability', 30)` raises emigration within 12 months; no vital changes when a slider moves with the producing systems stubbed to zero.

### 3.2 G2 sectors

**State** `g.sectors` (`newSectors(nid)` from `src/data/sectors.js`; ids agri, energy, extract, heavy, elec, defind, services; each with an `era` for F16 and optional later sectors ai, fusion, orbital):
```
{ [sid]: { cap, util, fill, cov, out, price, need:{basic,sec,ter}, inputs:{ [sid|mineral]: coef }, proj:{ prog, levers:[] } } }
```
**Monthly update** (phase `sectors`, after pops):
1. Labour fill: `fill_s = min(1, Σ_e min(labour_e, need_se × cap_s) / (Σ_e need_se × cap_s))`, labour allocated by sector wage priority (defind and elec first, services last); jobs written back to `pops.jobs`.
2. Input coverage: `cov_s = min_i (supply_i / (coef_is × cap_s))`; `supply_i` = domestic `out_i` + imports; imports priced at world price × (1 + settlement cost from F14) and zeroed by an embargo or export control against us. Semiconductors are an input of elec, elec of defind and heavy.
3. Output: `out_s = cap_s × fill_s^0.7 × cov_s × isolationCap(g)`, where `isolationCap` is F13's accessor.
4. Price (Vic3): `p_s = base_s × (1 + 0.75 × clamp((demand_s − out_s)/min(demand_s, out_s), −1, 1))`; demand = Σ_j coef_sj × cap_j + consumption(pops) + export demand from `g.demand`. Minerals keep their own price in `minerals.js`; one `worldPrice` helper serves both (QOL I5).
5. Capacity build, private (F5 shape): `margin_s = p_s × util_s / costBase_s / hurdle × demandPressure_s / saturation_s × capitalAccess(g)`; builds when margin > 1 at `pace` per month into `proj.prog`; levers (credit, loan, permit, guarantee) reuse `MINERAL_RULES.levers`. `defind` is state-directed: capacity grows with `budgetAlloc.defense` and shrinks when unfunded.
6. Outputs: `gdp = Σ out_s × p_s` replaces the notional `gdpBase` in the tax engine; `gdpGrowth` target = 12-month change of gdp; exports = max(0, out − domestic demand) × lane factor into `cash('Exports')`; `defind.out` × mineral coverage sets tranche speed (one `trancheRate(g)` function replaces the minerals-only slow factor); `agri.out / foodNeed(pops)` is the food-security target; `services.out / pop` is the schooling and health capacity used by G1.

**Formulas:** `labourFill`, `inputCoverage`, `sectorOutput`, `marketPrice`, `buildMargin` (shared with minerals: lift the current minerals margin into formulas.js and call it from both, rule 8), `sectorGdp`, `trancheRate`, `foodTarget`.
**Invariants:** every cap, out, price finite and ≥ 0; util, fill, cov in [0, 1]; gdp > 0; Σ jobs ≤ labour force; `proj.prog` ≤ build months.
**MVP:** seven sectors, one good each, a 7×9 coefficient matrix (seven sectors plus rare earths and semiconductors as mineral rows), fixed prices in the first PR (price formula in the second), fill and coverage only, GDP as the sum. Rivals: capacity scalar per sector from WDI shares, no private build.
**Done-when test:** embargo semiconductors for 36 months: elec output falls ≥ 25% within 12 months, then a dependent tranche slows measurably; building domestic elec capacity (levers on) restores output over ≥ 36 months; GDP equals Σ out × p to the cent every month; sanctions on us lower `isolationCap` and the top program tier becomes unreachable (F13).

### 3.3 G3 politics

**State** `g.politics` (`newPolitics(nid)` from `src/data/politics.js`):
```
{ regime: 'electoral'|'authoritarian', term: 48|null, next: month|null,
  f: { business:{clout, appr, trend}, labor:{...}, military:{...}, nationalists:{...}, technocrats:{...}, regional:{...} },
  legit: 0..100, unrest: 0..100, capital: 0..100, corruption: 0..100,
  edicts: { [eid]: since }, cabinet: { defense: fid, economy: fid, interior: fid } }
```
**Monthly update** (phase `politics`, after counterIntel, before world):
1. Clout (shares sum to 1): business = sector profit share (`sectors`) or treasury growth before G2; labor = employed share in agri, extract, heavy; military = active / pop × 100 + defense budget share; technocrats = tertiary share (pops) or education/100; nationalists = 0.5 × max tension/100 + pariah + blockades; regional = 1 − mean served (G4) or inequality/100 before G4. Hysteresis: a faction is "powerful" above 0.20 and stays until 0.18 (Vic3).
2. Approval target per faction: `tgt_f = clamp(Σ_k w_fk × term_k, −10, 10)` over ~14 terms already in state: taxPolicy deviation, each budget share, personnelPay, sanctions count, blockades, max tension, inequality, unemployment, healthcare, education, inflation, edicts, intel exposure (scandal), bloc trade with China or EU. Weights are one table in data, shown in the why-breakdown. Inertia (Democracy 4): `appr = appr + (tgt − appr)/4`.
3. Cabinet (CK3): each powerful faction without a seat takes −2 approval per month.
4. Legitimacy (Vic3 additive): `legit = base(regime) + 40 × Σ_f clout_f × appr_f / 10 + mandate − 0.3 × corruption − 0.2 × unrest`, clamped; levels at 25, 50, 75, 90 gate edict speed and unrest growth.
5. Unrest (7kaa lag, Vic3 radicals): `unrest += Σ_f clout_f × max(0, −appr_f) × 0.15 − 0.3 × (legit/100)`; thresholds 25, 50, 75 add stability penalties and events.
6. Stability target for `naturalDrift`: `stabEq = 0.6 × legit + 0.4 × (100 − unrest)` replaces `e.stability`.
7. Political capital: +`legit/50` per month, capped 100; each edict toggle or budget change beyond 10 points costs capital (Democracy 4 marks on the slider).
8. Corruption: `+0.05 × (budget size / gdp) − 0.1 × technocrats.clout − audits`; drains `cash('Corruption', −k × spend)` and slows every `proj.prog`.
9. Loss: electoral at `next`: `winP = sigmoid((Σ clout × appr − 0) / 3)`; defeat ends the run with a domestic game-over card. Authoritarian: `coupP/mo = base(regime) × (military.appr < −5) × (100 − legit)/100 × (1 − stability/100)`, base from Powell-Thyne-calibrated per-regime table; an uprising when unrest ≥ 75 for 12 months. Both go through the existing game-over gate.

**Formulas:** `factionClout`, `approvalTarget`, `legitimacy`, `unrestStep`, `stabilityTarget`, `electionOdds`, `coupOdds`, `corruptionStep`.
**Invariants:** clout shares sum to 1 ± 0.01; appr in [−10, 10]; legit, unrest, capital, corruption in [0, 100]; `next` is null or a future month; the player never appears in another nation's factions.
**MVP:** six factions, 14 terms from existing state (no G1 or G2 needed; clout swaps to pops and sectors when they land), legitimacy, unrest, two loss paths, six edicts, cabinet. This is the smallest epic and the only one that adds a loss condition.
**Done-when test:** warmonger bot wins every external contest in a seeded 240-month run and loses domestically before month 240 when tax is 48% and budgets favour defense 2.5×; stability equals its faction-derived target ± noise after 24 months; every edict's `fx` moves at least one faction by ≥ 1 in the test; `__wl.faction(id, appr)` hook exists.

### 3.4 G4 close the loop and domestic logistics

**State** `g.domestic` (`newDomestic(nid)` from `src/data/domestic.js`: 4 to 6 named domestic regions per playable nation with population share and sector mix, `status_source` on each; rivals get one region):
```
{ r: { [drid]: { pop, cap, usage, served, mix:{ [sid]: share } } }, links: [[a, b, cap]], invest: 0..200 }
```
**Monthly update** (inside `sectors` and `pops`, plus a small `logistics` step before them):
1. Usage: `usage_r = pop_r × (Σ_s mix_rs × out_s) / pop`. Access (Vic3): `access_r = clamp(cap_r / usage_r, 0, 1)`. Served is a rating (OpenTTD): `served_r += clamp(access_r × conn_r − served_r, −0.02, 0.02)`.
2. Sector output per region: `out_s = Σ_r out_s × mix_rs × (0.5 + 0.5 × served_r)`.
3. Services per region feed G1 targets weighted by population; `regional` faction clout reads `1 − mean served`; internal migration moves 0.1% per month from the least to the most served region.
4. Capacity: `cap_r` grows with a new `budgetAlloc.infrastructure` line and with logistics hubs, ports and processing nodes placed in that region on the map (F9 nodes inside the home region count as domestic; F11's lane rule applies to import lanes). Capacity decays 0.2%/month unfunded.
5. The loop arrows, one function each in `formulas.js`, each with a test: `taxBase(sectors)`, `budgetPool(revenue, debt)`, `capacityGrowth(margin, levers, capitalAccess)`, `jobsFilled(pops, sectors)`, `schoolFlow(pops, alloc, capacity)`, `sectorOutput(cap, fill, cov, served)`, `forceQuality(stats)` (exists), `rdSpeed(retention, terShare)`, `exportRevenue(out, demand, lanes, dominance)`, `influenceGain` (exists).

**Invariants:** cap, usage ≥ 0; served in [0, 1]; region population shares sum to 1 ± 0.01; every `mix` key is a sector id.
**MVP:** four regions per playable nation, served as one scalar, infrastructure as a budget line, no link graph, no routing library. Rivals one region (served = 1).
**Done-when test:** a 240-month turtle-bot run records `history` (Q5) and the test asserts the lagged chain: education spend at t correlates positively with tertiary share at t+60, with `rdSpeedMult` and elec output at t+84, with tax revenue at t+96; zeroing each arrow function in turn (test hook) degrades the next stock by ≥ 10% within 36 months; a region with `cap = 0` loses ≥ 30% of its output and raises `regional` unrest within 24 months.

### 4.2 Slider and drag patterns on touch

- **Precision:** NN/g (via [Guidewire's summary](https://docs.guidewire.com/jutro/documentation/10.13/slider) and [Semrush's](https://developer.semrush.com/intergalactic/components/slider/slider) [snippet]) says sliders suit approximate ranges and users drop the thumb off target when lifting a finger. Copy: pair every slider with a numeric stepper, snap to detents, commit on release.
- **Targets:** WCAG 2.2 asks 24px minimum with 24px spacing along a slider ([Deque](https://docs.deque.com/devtools-mobile/2024.9.18/en/ios-touch-target-spacing)); Apple's 44pt is already the shell rule. Material's 48dp slider area could not be read from an M3 page (unverified).
- **Number scrubbing:** Figma's Option-drag on a numeric field with speed by cursor distance ([Figma forum](https://forum.figma.com/report-a-problem-6/option-drag-to-change-values-is-inconsistent-36984)), [Webstudio docs](https://help.webstudio.is/mouse-dragging-property-values-qLN0jJJHl18N), [Angular directive write-up](https://dev.to/angular/figma-like-input-field-in-angular-using-directives-2g3c) [snippet]. Copy on desktop: drag any figure to change it; on touch, vertical distance sets precision.
- **Haptic detents:** one `selectionChanged` per detent crossing, never per pixel ([Swift with Majid](https://swiftwithmajid.com/2019/05/09/haptic-feedback-in-ios-apps/), [haptic_kit](https://pub.dev/packages/haptic_kit/versions/2.1.0)) [snippet]. Web: `navigator.vibrate(5)` on crossing where supported (Android); iOS Safari has none, so pair with a visible tick.
- **Preview before commit:** Civ VI shows "+N" yields on candidate hexes before placing ([Steam thread](https://steamcommunity.com/app/289070/discussions/0/4594236462781392613)); Anno draws the radius and highlights affected buildings while placing ([Harbourmaster's Office](https://anno1800.fandom.com/wiki/Harbourmaster%27s_Office)); Fluid's drag preview snaps back on a rejected drop ([Fluid wiki](https://fluidproject.atlassian.net/wiki/spaces/fluid/pages/11608104)) [snippet]. ## 5. Sequenced build plan

Order: **G1 → G3 → G2 → G4**, interaction work I1 with G3 (the first new sliders with faction costs), I2 and I3 with G2 and G4. Reason for moving G3 ahead of G2: G3's MVP reads only existing state, is the smallest epic, and is the only one that adds the domestic loss condition the spec names as the biggest gap ("today the player can only lose externally"). G2 is the largest and depends on G1's labour pool, so it benefits from G1 having settled first. If the owner keeps G1, G2, G3, G4, nothing below changes except the dependency lines.

Dependencies on F11 to F16 (issues exist for F11 [#69](https://github.com/delibremade/world-leaders/issues/69), F12 [#70](https://github.com/delibremade/world-leaders/issues/70), F14 [#71](https://github.com/delibremade/world-leaders/issues/71); F13, F15, F16 are spec-only so far):
- **F13 before G2.** F13 should land `isolationCap(g)` over today's proxies (sanctions, embargoes, pariah, minerals cap, defLevels). G2 adds the sector terms to that one function. Without F13 first, G2 would invent a second cap.
- **F14 before G2.** F14's `capitalAccess(g)` and settlement cost feed the G2 build margin and import price. If G2 lands first it stubs both at 1.
- **F12 with G2.** F12's "gated by the thief's industrial base" reads `sectors.defind.cap` and `sectors.elec.cap`; until G2 it reads defLevels. One accessor `industrialBase(g)`, swapped once.
- **F11 before G4.** G4 reuses F11's lane model for import lanes and F9's node types for domestic hubs; G4 adds the domestic region each node sits in.
- **F15:** no coupling.
- **F16 shapes G1 and G2 data.** Cohort rates must stay bounded to 2100 (ageing in Japan, Germany, China is the long-game story), and the sector registry carries an `era` field from the first PR so later sectors slot in without a migration.
- QoL: Q5 history (#45) makes the G4 loop test a one-liner; Q3 alerts (#43) carries "sector starved of input" rows; Q10 standing orders (#50) is the home of I3.
